# v3.0.0-rc.1 — telemetry backend simplification

This prerelease contains the matching Flutter and backend version-2 telemetry
implementation. Real Android/CAN qualification remains pending; use it for
qualification before a production cutover.

## Breaking changes and setup

- Use the phone and server sources from this same tag. Old/new MQTT payloads and
  schemas cannot be mixed. Existing telemetry is not migrated.
- Start fresh dedicated application database/broker/CSV storage using the
  [targeted cutover runbook](https://github.com/lugilugi/ect-dashboard/blob/v3.0.0-rc.1/docs/implementation/cutover.md).
  Ordinary startup preserves and rejects mismatched database volumes.
- The phone's one-time telemetry-storage reset preserves connection, USB, GPS and
  UI preferences. The server remains independent of the phone's live display and
  command/deadman processing.
- Both Docker layouts are included in the tagged source; follow the
  [backend setup guide](https://github.com/lugilugi/ect-dashboard/blob/v3.0.0-rc.1/BACKEND_GUIDE.md).

## Implementation

- One recorder assigns immutable per-metric timestamps/session/lap/source context.
  One real SQLite journal and one MQTT sender replace legacy queue/replay paths.
- Signals arrive independently and metadata can arrive late; new metric names
  need no SQL column. PUBACK remains broker handoff, not a SQL receipt.
- A narrow typed TimescaleDB schema, validated ingest views, shared analytics and
  corrected Grafana freshness/energy/lap/GPS behavior replace legacy conventions.
- Local CSV recovery and the independent server CSV archive remain available.
  Shared snapshot, reconciliation and original-identity replay tools are included.
- Both Docker layouts share core versions/configuration, bounded database roles,
  schema fingerprints and CSV downloads. Unsupported temperature/auxiliary-energy
  panels and placeholder numeric values are removed.

## Verification and remaining gate

Local checks passed: 91 Flutter tests, 10 Python tests, 53 Grafana queries, and
both layouts with actual Dart CAN decoding → recorder → SQLite → MQTT → SQL/CSV.
All 41 capture records and all 121 outage/restart records reconciled with their
immutable context. Tests cover database/Telegraf outages, duplicate/conflicting
input, delayed metadata, compressed replay, fresh initialization, exports and
CSV repair. Default/custom settings and mismatched-volume preservation passed.

The release workflow builds the APK with the existing signing identity and an
increasing build number, and verifies its certificate before uploading.
Hardware USB/CAN/GPS, Android lifecycle/permissions, target-phone performance,
commands/deadman on hardware and abrupt-power-loss behavior remain unqualified.
The [verification record](https://github.com/lugilugi/ect-dashboard/blob/v3.0.0-rc.1/docs/implementation/verification.md)
separates software evidence from the pending hardware gate.
